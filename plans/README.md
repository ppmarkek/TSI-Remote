# Планы реализации

Планы перечислены в рекомендуемом порядке. Перед началом работы исполнитель
должен полностью прочитать выбранный план, соблюдать его границы и условия
остановки, а после завершения — обновить статус в этой таблице.

## Порядок выполнения и статус

| План | Название | Приоритет | Объём | Зависит от | Статус |
|------|----------|-----------|-------|------------|--------|
| [001](001-cross-platform-improvement-roadmap.md) | Сделать Konspekt надёжным, удобным и нативным на Windows и macOS | P0 | L | — | DONE |

Допустимые статусы: `TODO`, `IN PROGRESS`, `DONE`, `BLOCKED: <причина>` или
`REJECTED: <причина>`.

## Зависимости

- Этапы плана 001 выполняются последовательно: сначала безопасность и
  сохранность данных, затем платформенный слой и управление процессом, после
  этого упаковка, UX и дополнительные учебные функции.
- Релиз для macOS нельзя считать готовым только по результатам запуска из
  исходников: обязательны проверка собранного `.app`, подпись и notarization.

## Осознанно отложено

- Linux не входит в текущую матрицу поддержки. Платформенный слой не должен
  мешать будущему порту, но отдельный Linux-релиз сейчас не планируется.
- Автоматическая отправка материалов внешнему провайдеру без подтверждения
  пользователя не рассматривается: передача данных всегда требует явного
  согласия.
- Импорт локальных аудио, видео и PDF выполняется только после стабилизации
  основного сценария BBB → конспект на Windows и macOS.
- Фоновое автообновление приложения откладывается до появления стабильного
  подписанного канала релизов.
