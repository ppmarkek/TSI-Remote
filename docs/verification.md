## 2. Локальная настройка окружения

### Проверка текущей локальной ветки
До первого `push` проверку нужно выполнять именно в текущей рабочей копии:

```bash
cd /Users/a-/Documents/GitHub/TSI-Remote
git switch work/konspekt-cross-platform
```

### Клонирование после публикации ветки
После независимого ревью, коммита и публикации ветки можно воспроизвести проверку в новом клоне:
```bash
git clone https://github.com/ppmarkek/TSI-Remote.git
cd TSI-Remote
git switch --track origin/work/konspekt-cross-platform
```

### Подготовка виртуального окружения
```bash
# Создание окружения через uv
uv venv .venv
source .venv/bin/activate  # macOS / Linux
# или .venv\Scripts\activate  # Windows

# Установка зависимостей проекта
uv sync
```

## 3. Команды верификации качества кода

### 3.1. Запуск набора модульных тестов
- **macOS / Linux**:
  ```bash
  PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
  ```
- **Windows (Command Prompt / PowerShell)**:
  ```cmd
  set PYTHONPATH=src
  .venv\Scripts\python -m unittest discover -s tests -v
  ```

### 3.2. Статический анализ и проверка форматирования (Ruff)
```bash
# Проверка линтером (исключает bbb_import.py согласно pyproject.toml)
.venv/bin/ruff check .

# Проверка соответствия форматированию
.venv/bin/ruff format --check .
```

### 3.3. Проверка чистоты Git diff
```bash
git diff --check
```

## 4. Сборка пакетов и Smoke-тестирование

### 4.1. Сборка дистрибутива
```bash
# macOS (создает Konspekt.app и Konspekt.dmg)
.venv/bin/python scripts/build_package.py

# Windows (создает Konspekt.exe в dist/Konspekt/)
.venv\Scripts\python scripts\build_package.py
```

### 4.2. Автоматическое Smoke-тестирование дистрибутива
Скрипт выполняет проверку изоляции `PATH`, валидацию диагностического контракта в формате JSON и условную верификацию жизненного цикла GUI:
- **Диагностический контракт (non-GUI)**: выполняется всегда, проверяя изоляцию окружения, доступность упакованных бинарных зависимостей (`ffmpeg`, `tesseract`), права на запись в системные каталоги и целостность манифеста.
- **Тест жизненного цикла GUI (`--smoke-test-gui`)**:
  - Запускается автоматически при наличии подтвержденной интерактивной графической сессии (активный WindowServer Aqua на macOS, интерактивный рабочий стол на Windows, `DISPLAY`/`WAYLAND_DISPLAY` на Linux).
  - В headless-окружениях (CI-раннеры, SSH-подключения, фоновые агентские сессии) GUI-подэтап безопасно пропускается с диагностическим сообщением, предотвращая ложные инфраструктурные отказы.
  - Если GUI-проверка запущена, сбои жизненного цикла не маскируются и приводят к ненулевому коду завершения.

#### Стандартный запуск (с автоматическим определением сессии)
```bash
# macOS
.venv/bin/python scripts/smoke_package.py

# Windows (PowerShell / Command Prompt)
.venv\Scripts\python scripts\smoke_package.py
```

#### Принудительный запуск проверки GUI (Explicit Opt-in)
Для явного включения проверки жизненного цикла GUI операторам следует задать переменную окружения `KONSPEKT_GUI_SMOKE=1`:
- **macOS / Linux**:
  ```bash
  KONSPEKT_GUI_SMOKE=1 .venv/bin/python scripts/smoke_package.py
  ```
- **Windows (PowerShell)**:
  ```powershell
  $env:KONSPEKT_GUI_SMOKE="1"; .venv\Scripts\python scripts\smoke_package.py
  ```
- **Windows (Command Prompt)**:
  ```cmd
  set KONSPEKT_GUI_SMOKE=1 && .venv\Scripts\python scripts\smoke_package.py
  ```

> [!IMPORTANT]
> При сбое GUI smoke-теста (ненулевой код возврата, аварийное завершение или таймаут) скрипт завершается с ошибкой. Сбои не маскируются — оператор обязан устранить первопричину неполадки и повторно запустить проверку.

## 5. Процедура ручного тестирования

### 5.1. macOS
1. **Запуск приложения**: Открыть созданный образ `dist/Konspekt.dmg` или запустить бандл `dist/Konspekt.app`.
2. **Типографика и интерфейс**: Проверить четкость шрифтов (Helvetica Neue, Menlo), работу темной/светлой темы, оптическое выравнивание и анимации (или их отключение с `--reduce-motion`).
3. **Горячие клавиши**: Убедиться в корректной работе платформенных сочетаний (`⌘V` для вставки ссылки, `⌘O` для открытия файла).
4. **Импорт и обработка**:
   - Импортировать ссылку на BBB-лекцию или локальный аудио-/видеофайл.
   - Убедиться в генерации манифеста лекции `lecture-manifest.json` и хешировании контента.
   - Проверить извлечение аудио через FFmpeg и распознавание Whisper.
5. **Экспорт**: Проверить выгрузку в чистый HTML и автономный PDF 1.4 с корректным отображением кириллицы и оглавления.
6. **DeepSeek / ChatGPT Handoff**: Проверить валидацию данных перед передачей в буфер обмена и браузер.

### 5.2. Windows
1. **Запуск исполняемого файла**: Запустить `dist\Konspekt\Konspekt.exe`.
2. **Типографика и системные соглашения**: Проверить шрифт интерфейса (Segoe UI, Consolas), нативные диалоговые окна и интеграцию с WebView2.
3. **Горячие клавиши**: Проверить сочетания с клавишей `Ctrl` (`Ctrl+V`, `Ctrl+O`).
4. **Безопасность настроек**: Проверить автоматическую миграцию устаревших DPAPI-секретов в системный `keyring` (Windows Credential Manager) и очистку `settings.json`.
5. **Изоляция и производительность**: Убедиться в отсутствии блокировок фоновыми потоками и корректном завершении дочерних процессов при отмене.

## 6. Политика безопасности и работы с секретами

1. **Хранение учетных данных**:
   - Запрещено сохранять открытые API-ключи, токены или пароли в файле конфигурации `settings.json` или в текстовых журналах.
   - Для хранения секретов используется системное защищенное хранилище (`keyring`: macOS Keychain / Windows Credential Manager).
2. **Санитарная очистка исходящего контекста**:
   - Перед отправкой во внешние LLM-провайдеры (OpenAI, DeepSeek, ChatGPT Account) весь контекст проходит строгую валидацию и фильтрацию.
   - Автоматически удаляются и блокируются: приватные URL/токены запроса, локальные абсолютные пути (Unix, Windows, UNC), идентификаторы UUID, meeting ID, GitHub PAT, AWS credentials, ключи API и токены аутентификации.
   - Проверяются лимиты контекста для каждого конкретного провайдера.
3. **Диагностические журналы**:
   - Файл журнала `konspekt.log` формируется без тел HTTP-запросов, заголовков авторизации и конфиденциальных пользовательских путей.
4. **Контроль версий**:
   - Запрещено коммитить файлы с секретами, переменные окружения, дампы библиотек или артефакты сборки.

## 7. Регламент действий при сбоях (Mandatory Failure Procedure)

1. **Немедленная остановка**: При обнаружении непройденного теста, ошибки линтера или сбоя smoke-теста (включая сбой GUI-подэтапа при активной графической сессии или явном opt-in `KONSPEKT_GUI_SMOKE=1`) процесс сборки/релиза немедленно прекращается.
2. **Изоляция и диагностика**:
   - Изучить журнал `konspekt.log` в директории приложения.
   - В случае повреждения библиотеки `library.json` проверить создание резервной копии `library-corrupt-*.json` (карантин поврежденных строк без потери валидных лекций).
3. **Устранение причины**:
   - Исправить ошибку исключительно в рамках разрешенной зоны ответственности модулей.
   - Убедиться, что файл `src/konspekt/bbb_import.py` остается байт-в-байт идентичен коммиту `6af6eb33ebe9439ed47043aac26ced4cf4c3fdde`.
4. **Повторная полная верификация**:
   - Повторно выполнить весь цикл проверок: unit-тесты, `ruff check`, `ruff format --check`, `git diff --check`.
   - Релиз допускается только при 100% успешном прохождении всех валидаций.
